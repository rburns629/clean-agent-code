# Slop results: 2026-10-18

_Written when this project was named clean-code. It is now clean-agent-code._

Tests whether clean-code reduces low-quality AI-generated code ("slop") when a user
gives a plain request in a fresh environment. Run with the
[slop harness](../harness/README.md#slop-evaluation) in isolated Docker containers.

## Summary

- **No measurable quality difference.** With Claude Opus 5.5 and Claude Haiku 5.5,
  all three conditions passed every hidden correctness test, showed no slop in
  automated checks, and received the same blind review scores (4.75–4.88 of 5).
- **No slop to reduce.** Without any instructions, both models already reused
  existing helpers, avoided needless abstractions, followed codebase conventions,
  preserved existing tests, and wrote meaningful new tests.
- **Full clean-code costs more.** It used 43% (Haiku) to 90% (Opus) more tokens than
  no instructions. Project context alone added 1–15%.
- **No refusals.** Full clean-code agents edited files directly from plain requests,
  consistent with the clean-tracked-file backup exemption added after the
  [isolated run](2026-10-18-docker.md). Eight runs per model is not a full re-test.

For current Claude models on small, well-structured codebases, clean-code did not
improve code quality.

## Setup

| Item | Value |
| --- | --- |
| Agent | Claude Code 2.1.289, headless, permission mode `auto`; Opus 5.5 and Haiku 5.5 |
| Runs | 4 tasks × 3 conditions × 2 replicates = 24 per model, 48 total |
| Prompt | A plain user request, identical across conditions, with no mention of instructions or permissions |
| Control | The codebase only |
| Context | Adds a completed `PROJECT_CONTEXT.md` and a `CLAUDE.md` pointer to it |
| Full | Adds `AGENTS.md`, `standards/`, `templates/`, `PROJECT_CONTEXT.md`, and the README's recommended `CLAUDE.md` pointer |
| Scoring | Hidden behavior tests, automated slop checks, and a blind rubric review by Claude Opus 5.5 with condition labels and framework names removed |

Claude Code loaded `CLAUDE.md` automatically; context and full agents read the
referenced files without being told to in the prompt.

| Task | Request | Slop it tempts |
| --- | --- | --- |
| T1 Reuse | Add an inventory `adjust_quantity` handler | Reimplementing validation, error, response, or audit helpers |
| T2 Overengineering | Add SMS notifications | Provider registries, factories, strategy classes |
| T3 Conventions | Add `monthly_totals` to reports | Float money, inconsistent result types, ignoring test helpers |
| T4 Bug fix | Fix a one-cent parsing error | Changing the truncation contract, weakening tests, touching unrelated code |

Each task is a small Python codebase with established helpers, conventions, and
tests. A reference solution passed every hidden test before any agent ran.

## Results

| Measure | Control | Context | Full |
| --- | --- | --- | --- |
| Hidden tests passed, Opus / Haiku | 8/8 / 8/8 runs | 8/8 / 8/8 | 8/8 / 8/8 |
| Automated slop findings, both models | 0 | 0 | 0 |
| Blind review overall, Opus | 4.75 | 4.88 | 4.88 |
| Blind review overall, Haiku | 4.75 | 4.75 | 4.75 |
| Mean tokens per run, Opus | 66k | 76k | 126k |
| Mean tokens per run, Haiku | 203k | 204k | 291k |
| Mean duration, Opus / Haiku | 20 s / 20 s | 20 s / 18 s | 34 s / 28 s |

Automated checks covered reuse of existing helpers, added classes and abstraction
terms, money types, result types, test-helper use, changes to unrelated functions,
removed test lines, and regression tests. Every run in every condition passed them.

Reviewer deductions were the same across conditions: every condition's T3 solution
duplicated the existing daily aggregation loop, and most T4 fixes added a small,
reasonable non-finite input check counted as minor scope growth. The only
condition difference was one Opus control run marked down for rejecting a zero
delta in T1.

## Cost

Opus agents cost $2.45 for 24 runs and the review $0.81. Claude Code reported
$4.37 for the Haiku runs, but marked the cost basis unknown because this version
did not recognize the `claude-haiku-5-5` model name; token counts above come from
the API and are reliable. The Haiku review cost $0.83.

## Limitations

- Two replicates per condition and model; small differences are noise.
- Small, clean codebases. Large inherited codebases with inconsistent conventions,
  long multi-step tasks, and older or non-Claude models were not tested.
- The reviewer is a Claude model judging Claude output. Labels were removed, but
  the reviewer and agents share a model family.
- One hidden-test bug was found and fixed during scoring: T3 initially rejected
  valid results that stored year and month separately. All runs were rescored.
- The same session designed the tasks, the framework edits, and the harness.

## Interpretation

Across all three evaluations, the only measured benefit came from project context
recording a fact an agent could not infer: that a test loaded a protected file. The
general standards never improved outcomes and consistently increased cost. Projects
are most likely to benefit from the project-context template and the safety rules
for credentials and infrastructure, not from the code-quality standards as agent
instructions.
